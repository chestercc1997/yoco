# gRet 第 9793 步修复与两个历史异常的归因

2026-11-18。830M 第 9793 次尝试的首个 Inf 已定位到**每个块写入递推状态的矩阵乘法**。修复已通过实际故障权重和输入的前反向检查。400M 第 14311 步和 160M 第 21354 步缺少原始触发权重，各自能验证的现象见下文。

## 830M 的第一个 Inf 在哪里

两次回退和最后一次失败都发生在 rank 1、microbatch 2。三份现场文件的 SHA-256 完全相同，为 `12c6ee347d2df5c77ae998fd50cad998ecb6b7e4ffc676730e60cd41cc37db39`。回放沿用冻结配置，FP16 mixed、FP32 参数、loss scale 128、确定性算法开启。

每个块先计算门衰减后的 V，再通过 `Kᵀ @ weighted_V` 产生对后续块的状态增量。旧版在矩阵乘法输出处先写成 FP16，随后才转入 FP32 状态。第一层各项的实测结果如下。

| 顺序 | 观测 |
| --- | --- |
| Q、K、V、门、加权 V | 均有限；之前已修复的块内加权和也有限 |
| 状态增量 | 仅索引 `[0, 5, 5, 211, 57]` 溢出，依次为样本、头、块、键通道、值通道 |
| 独立参考 | 对这一元素，取参与原 GEMM 的已舍入输入做 FP64 点积，得到 **65911.346838**；FP16 最大有限值为 **65504** |
| 传播 | 污染后面两块共 **512** 个归一化前输出，旧版完整模型 loss 为 NaN |

本轮修改复用了块内求和已有的异常处理。状态写入仍先走原 GEMM；当检测到非有限结果，用相同的已舍入操作数在现有状态累积类型中重算该乘积，只替换非有限元素。回放中对应元素恢复为 **65911.1875**，其余原本有限的状态增量逐元素相同。该路径增加了对每次状态写入的有限性检查，未测量吞吐影响。训练配置、归一化、FP16 激活接口、AdamW 和 AMP 参数均沿用冻结版本。[代码](../runtime/yoco_official/backend.py) · [逐元素与完整模型回放](evidence/gret-830m-state-write-9793.json)

| 验证 | 结果 |
| --- | --- |
| 同一故障 microbatch | loss **3.205361**；FP32/TF32 诊断参考 **3.204920**；按原 scale 和累积系数反向，221 个参数梯度均有限 |
| 同一故障权重，八卡完整更新的前反向 | 原 128 条样本、32 个 microbatch 全部 logits 与 loss 有限，故障卡输入和标签与快照逐项一致；全局 loss **3.318346**，各卡反缩放后的裁剪前梯度范数均为 **0.756839**，未执行优化器更新 |
| 健康权重对照 | 同一输入换用真实 5004 步权重；新旧 loss 均为 **3.281692**，221 个梯度张量逐位相同 |
| 之前的现场 | 830M 第 5926、6438、6494 步和 400M A 第 24935 步均再次通过前反向检查 |
| 恢复点 | 八卡分别加载原 5004 步完整 checkpoint；每卡 887 个张量受检，模型、AdamW、scaler 与各卡 RNG 在首次前向前逐位一致 |

830M 正式训练仍暂停。用于诊断的快照仅保存故障状态；未来接续应使用原 5004 步**完整** checkpoint 和含本轮修复的新代码。恢复入口校验 checkpoint 和变更文件的 SHA；仅替换后端的恢复还要求整份配置一致。旧训练目录和故障快照均保留。[既往现场复测](evidence/gret-state-write-prior-snapshots.json) · [八卡故障步回放](evidence/gret-830m-state-write-full-update.json) · [八卡恢复证据](evidence/gret-830m-state-write-exact-restore.json) · [验证脚本](../tools/check_gret_9793.py)

## 官方计算路径在同一输入上的结果

在 A100 上提取本地 9793 步快照第一层的 Q、K、V 和门值，沿用该现场的 256-token 分块，调用微软公开的 `cross_chunk`。在递推内核入口读取刚算出的状态增量，两次均使用同一组源张量。BF16 对照将 V 和门值按 BF16 舍入，再在 BF16 autocast 下计算。被检查的是同一个位置 `[0,5,5,211,57]`。

| 官方状态增量计算的执行方式 | 该位置的值 | 整个增量张量的非有限元素数 |
| --- | ---: | ---: |
| FP16 autocast | Inf | 1 |
| BF16 autocast | 66048 | 0 |

这将归因进一步缩小到状态增量写回 FP16 的边界。保留官方乘法表达式，也能用本地权重产生同一个 Inf。微软公开的预训练命令推荐 BF16，65911 附近的幅度处于其有限范围内。这里仅验证状态写入；本机 Triton 未能编译该版本后续递推函数中的类型注解，因此没有得到完整官方内核或从头训练的对照结果。官方源文件 SHA-256 为 `5ffe76f10feb2789c460893357f7ffc7510b5c16c460071535ab2a25e88e090e`。[官方内核](https://github.com/microsoft/unilm/blob/master/YOCO/yoco/models/decoder/kernel/gate_recurrent.py) · [官方预训练说明](https://github.com/microsoft/unilm/blob/master/YOCO/README.md#pretraining-from-scratch)

## 400M A 第 14311 步为何重放不出原故障

原训练日志记录 rank 3 前向 loss 非有限。可用的 14310 步快照来自**后来重放**。本次逐步对齐两条运行的 rank 0 日志，比较从同一 10000 步 checkpoint 接续后的共同区段。

| 最早有记录的差异 | 原训练 | 同冻结代码重放 |
| --- | ---: | ---: |
| 10001 步，裁剪前梯度范数 | 0.3302188814 | 0.3302194476 |
| 10002 步，loss | 3.1949942112 | 3.1949963570 |
| 11499 步，裁剪前梯度范数 | 11.98035 | 0.29867 |
| 11853 步，已接受更新的 scale 首次不同 | 4096 | 2048 |
| 13937 步，裁剪前梯度范数 | 39.94743 | 0.30018 |

重放在第 14311 步得到有限的全局 loss **3.116775**。在第 10001 步取 rank 3 的真实输入、权重和首个 cross-attention 的上游梯度，重复调用冻结代码的原生 SDPA 三次：前向输出相同，Q 梯度最大绝对差 **9.54 × 10⁻⁷**；启用确定性执行后的三次结果完全相同。这直接验证了一处可能使重放分岔的反向运算。探针隔离了原生算子，原始训练使用层编译和八卡 DDP，因此无法据此指定原训练首次梯度差的唯一来源，也无法确定 14311 步哪个前向算子首先失败。[对齐记录](evidence/gret-400m-14311-trajectory.json) · [同输入反向复测](evidence/gret-400m-10001-attention-repeat.json) · [历史重放](evidence/400m-A-failure-review.json)

## 160M 第 21354 步是有限梯度尖峰

原日志在尝试该步时连续拒绝三次反向，scale 依次退到 64、32、16；成功尝试的**裁剪前**梯度范数为 991.3059，训练按原阈值 1.0 裁剪。旧 trainer 调用手动 scale 回退时未清零连续成功步计数。第 21354 步成功后，scale 在第 22000 步就回升到 32，距离最近的回退不足默认增长间隔 2000 个成功步。现有 trainer 已修复计数，并验证了本卡及其他卡触发拒绝时的行为。这个计数缺陷解释了过早回升；回升时间晚于首次尖峰。[160M 原日志审计](evidence/baseline-numerical-audit.json) · [scaler 回归](evidence/400m-A-amp-backoff-check.json)

本次用原冻结实现和第 21354 步全部 128 条真实样本，对尚存的早期、晚期权重做了对照。单卡按原累积系数计算并反缩放；归约顺序与原八卡不同。FP32 仅供诊断，余弦比较同一权重、同一批次的 FP16 梯度与 FP32 参考梯度。

| 权重步数 | FP32 梯度范数 | FP16 scale 16 范数 / 余弦 | FP16 scale 128 范数 / 余弦 |
| --- | ---: | ---: | ---: |
| 100 | 0.8914 | 0.8960 / 0.9855 | 0.8898 / 0.9990 |
| 40000 | 3.5474 | 13.3660 / **−0.3884** | 2.4297 / 0.5977 |

晚期权重在两种 scale 下的 FP16 前向 loss 都是 **3.424441**。scale 仅作用于反向，反缩放后梯度的方向和幅度仍有明显差别。早期权重在同批数据上没有类似尖峰。由此可以确认晚期梯度对 FP16 反向舍入和缩放高度敏感；原第 21353 步权重已经缺失，无法还原将权重带到首次尖峰的直接触发运算。没有依据据此调整正式训练精度、scale 策略或 grad clip。[早期权重回放](evidence/gret-160m-21354-early-control.json) · [晚期权重回放](evidence/gret-160m-21354-late-control.json)
